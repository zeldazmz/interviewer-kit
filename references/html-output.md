# HTML 信息图规格（html-output.md）

产物形态：**单文件自包含 HTML 信息图**（微信长图友好），基于 `assets/template.html` 骨架填充数据生成。生成后按 html skill 规范自检与交付。

## 一、规格（固定约束，勿改）

- 内容宽度：桌面 750px 固定（微信主流阅读宽度），页面居中，背景浅色；**≤600px 视口走竖版真实排版**（画布 100% 宽、不再等比缩放，正文 ≥14px、主问题 17px、锚定/红旗卡单列、追问标签 96px+内容两列），600-820px 等比缩放过渡。
- **导出与竖版解耦**：导出期间给 body 加 `.exporting` 并强制克隆体 750px——竖版媒体查询全部以 `body:not(.exporting)` 为作用域，保证手机端导出的长图仍是 750px 桌面版式（导出后移除该类）。
- 字体：系统字体栈（`-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`），**不加载外部字体**。
- 字号：正文 ≥16px，说明 ≥14px，核心结论 ≥18px，标题层级清晰（手机查看长图可读优先）。
- 配色：沿用模板色板（深蓝主色 #1E2A44 + 橙色强调 #E8833A + 浅底 #EEF1F6），不要另造新色板。
- 导出清晰度：导出长图**自适应 scale**（按设备 canvas 上限自动缩放，最大 3x），单次渲染够用即单次（业务面/HR面单通道约 8000px 内容可到 2x），仅当被 scale≥0.75 下限抬升导致超限才分段；PNG 超 12MB 才转 JPEG，保证文字锐利。
- 单文件自包含：CSS/JS 内联（含 html2canvas 库本体），原生 JS，无构建依赖、**无外部 CDN 引用**（断网/内网可导出）；无 emoji，图标用内联 SVG。
- 不出现公司名等特定组织信息（通用发布型产物）。
- **数据合规**：产物属机密资料，仅限内部面试评估使用，禁止外发公网；导出文件名默认含候选人名，对外分享前可先编辑人选名为编号/化名再导出。

## 二、页面模块结构（自上而下，全部必需）

1. **头部**：人选名字（大字）+ 目标岗位 + 一句话核心标识 + 「面试建议」聚焦条（3 个聚焦胶囊，编辑模式可增删）
2. **匹配度与核心优势（合并卡）**：高/中/低徽章 + 一句话总结 + 分维度标签（达标/部分/缺口）+ 核心优势 3 条（同卡内分隔线分区）
3. **待考察点**：按维度分组，每条附风险等级标签（红线/核心/一般）与"面试中如何验证"
4. **业务面问题清单**：教学卡（主问题 / 考察维度 / 设计原理 / 高分锚定与红旗信号并排嵌入式卡片 / 追问路径带技巧标签）
5. **HR面问题清单**：按所选模式（模板四段 / 自由题组）
6. **时间分配与节奏要点**：业务面 30min 表 + **面试节奏要点卡**（开场铺垫 / 收尾 5 分钟 / 追问礼仪，editable 可改），上下排列、节奏要点卡独占整行；HR面不再输出时间表，节奏要点卡两场通用
7. **页脚**：生成说明 + 编辑/导出提示

头部含**水印条**「内部资料 · 仅限面试评估使用」（editable，可删）。

## 三、在线可编辑（模板已内置，生成时保留）

- 文本：`contenteditable`，点击即改（编辑模式开关控制）。
- 模块：问题卡可增删（删除按钮 + 底部"+ 添加问题卡"）。
- 工具栏：编辑模式开关 / 导出业务面 / 导出HR面 / 导出全部 / 重置为 AI 生成版本。
- 所有修改本地生效，刷新页面后可再改；导出的是当前编辑后的内容。

## 四、导出长图（分拆导出，三通道，断网可用）

- 主通道：`html2canvas`（**已内联进模板**，无外链），背景色与页面一致。
- **导出业务面**：克隆页面，仅保留头部+匹配度与核心优势+待考察点+业务面教学卡+业务面时间表+节奏要点，渲染 PNG——**可直接单独发给业务面试官**。
- **导出HR面**：克隆页面，仅保留头部+匹配度与核心优势+待考察点+HR面清单+节奏要点，渲染 PNG。
- **导出全部**：整页渲染 PNG。
- 稳定性机制：**自适应 scale**（按浏览器 canvas 单边上限 16384 自动限缩，最大 3x，留 16000 余量）；**单次优先**——整页 H×scale≤16000 时整段一次渲染（不克隆分片，更快更稳）；仅当被 scale≥0.75 下限抬升（H>21333）导致单次超限时才分段，段高按单段渲染上限动态计算；PNG 超 12MB 自动转 JPEG(0.92)（微信单图上限约 25MB，12MB 以下保持 PNG 保真）；成功/失败均有 toast 提示且按钮文案自动恢复。
- 兜底：`@media print` 打印样式。
- 导出文件名：`<候选人>-<岗位>-业务面问题清单.png|jpg` / `-HR面问题清单.png|jpg` / `-面试问题清单.png|jpg`（文件名取自 hero 中的名字，脱敏请先编辑该字段）。

## 五、生成步骤（Agent 执行）

1. 复制 `assets/template.html` 到任务目录（语义化目录，如 `resume-interview/<候选人>-<岗位>-面试清单.html`）。
2. 按本文件模块结构，把 analysis-framework 与 question-design 的结构化输出**填入对应模块**；模板中带 `data-sample` 的示例卡片全部替换为真实内容，不得残留示例文本。
3. 教学卡填充：高分锚定/红旗信号放入并排卡（.good-card/.bad-card）；追问路径 3-4 条、每条带 [技巧标签]。
4. 保留模板的编辑/分拆导出 JS 与工具栏不变。
5. 自检：用 html skill 的 `shot.py`（`python3 <html-skill>/scripts/shot.py <html路径>`）跑桌面+移动截图，修正 error 与影响阅读的问题。
6. 交付：`present_files` 交付该 HTML（artifacts[].name 写文件名）；交付后回复 ≤8 行，说明产物、编辑与三种导出方式。

## 六、英文产物适配

产物语言跟随**面试语言**（不跟操作者语言）。中文 HR 面英文候选人时：HTML 全英文，弹窗保持中文。规则详见 `en-localization.md`，此处只列呈现层差异：

- **命名**：`<Candidate>-<Role>-Interview-Guide.html`；导出 `<Candidate>-<Role>-Business-Interview.png|jpg` / `-HR-Interview.png|jpg` / `-Interview-Guide.png|jpg`
- **分发形态**：海外场景不用微信长图口径，默认 PNG 或打印 PDF，走邮件 / ATS
- **字号**：英文同等 px 下视觉更小，正文 16px、主问题 20px、说明 14px（中文模板 16/20/14 不变）
- **字体栈**：沿用现有 `-apple-system, "PingFang SC"…`，拉丁字符由 `-apple-system` 覆盖，不加载外部字体
- **文案膨胀**：同一内容英文通常比中文译文长约 15%，导出高度自适应，无需改分段代码
- **水印条**：`Internal Use Only · For Interview Evaluation`
- **页脚**：须含「非法律建议」免责声明（`en-localization.md` 第六节），提示 US 各州 / EU 各成员国 / UK 规定不同，正式使用前经当地法务复核
- **标签**：追问路径用英文短标签（Deep dive / Metric check / Stress test 等，见 `en-localization.md` 附录 B）；模块标题用 `Question` / `Follow-ups` / `Why this works` / `Strong signals` / `Red flags`

## 七、交付检查单

- [ ] 无示例文本残留（全文无 "data-sample" 内容）
- [ ] 桌面 750px 宽、正文 ≥16px、主问题 ≥18px；375px 竖版真实排版（无横向溢出、正文 ≥14px、主问题 17px）
- [ ] 七个模块齐全 + 节奏要点卡 + 水印条，内容来自分析/设计输出
- [ ] 每张教学卡追问路径 ≥3 条且带技巧标签；高分/红旗单条 ≤18 字
- [ ] 高分锚定/红旗信号为并排嵌入式卡片（蓝/橙配色）
- [ ] 无婚育/家庭情况类面试问题（合规）
- [ ] 编辑/三个导出按钮真实可用（非僵尸按钮）；html2canvas 已内联、无外链
- [ ] **导出业务面 PNG 含 30 分钟时间表与节奏要点**（B4 回归：biz 通道保留 `.ttable`，hr 通道删除）；导出全部时两者都在
- [ ] 导出失败时 toast 提示「导出失败」而非下载空白图；连续双击导出按钮不报错
- [ ] shot.py 无 error，桌面+移动截图已核对
- [ ] 导出文件名符合规范
- [ ] 英文产物：`<html lang="en">`、工具条/toast/确认框为英文、无中式英语、无 STAR 模板腔、页脚含免责声明、文件名用英文规范（见 `en-localization.md` 第九节）
