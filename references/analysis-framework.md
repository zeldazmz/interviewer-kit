# 简历分析框架（analysis-framework.md）

输入：简历内容（文件解析出的文本）+ 岗位画像（点选结果）+ JD（如有）。
输出：四部分结构化分析，是后续问题设计与 HTML 填充的数据源。

## 一、一句话核心标识

用一句话概括候选人最突出、可被识别的标签：**年限 + 职能/领域 + 最强成果或特征**。
示例：「5 年电商增长运营，主导双11 GMV 1.2亿→1.7亿（+42%）」

规则：
- 取简历中最高量级的成果/最连续的领域，不罗列。
- 写"可传播的一句话"，HR 分享给业务面试官时直接可用。

## 二、匹配度评估（按岗位画像逐维对照）

**维度来源**：有 JD 时，「岗位要求」列优先取 JD 提炼结果，并把 `jd_specifics`（映射不到标准维度的 JD 特有要求，如「熟悉 FDA 510(k) 注册流程」）作为补充行单列；无 JD 时取点选值；`profile_notes` 里的自由文本要求与点选值同权，冲突时以自由文本为准。

此外单列一组**成功要素对照**（2-3 条）：判断「这个人像不像在这个岗位上做得好的人」。它与逐维达标性是两条独立线索——逐维全达标但成功要素对不上，通常意味着招进来能干但不合适；成功要素标注「推断项」的，结论需注明置信度低。该组**不新增 HTML 模块**，作为匹配度总结句的判断依据与问题设计的锚点。

把岗位画像的每个维度与简历逐项对照，产出：

**总评**：高匹配 / 中匹配 / 低匹配（三档，给出 1-2 句依据）。

**分维对照表**（每行一个维度）：

| 画像维度 | 岗位要求 | 简历证据 | 判定 |
|---|---|---|---|
| 职能方向 | （点选值） | 候选人相关经历 | 达标/部分/缺口 |
| 职级层级 | （点选值） | 职责范围与带人情况 | 达标/部分/缺口 |
| 经验年限 | （点选值） | 相关年限 | 达标/部分/缺口 |
| 学历 | （点选值） | 学历信息 | 达标/部分/缺口 |
| 核心职责重点 | （点选值） | 对应经历 | 达标/部分/缺口 |
| 关键能力 | （点选值） | 技能/成果证据 | 达标/部分/缺口 |
| 行业背景 | （点选值） | 行业经历 | 达标/部分/缺口 |
| 协作形态 | （点选值） | 协作/管理经历 | 达标/部分/缺口 |
| 软素质（偏好） | （点选值） | 可推断信号 | 达标/部分/缺口 |

**降级规则**：
- 命中硬性红线（用户点选，如履历存疑/跳槽频繁/薪酬远超预算/行业完全无关）→ 总评直接降一档并加警示。
- 某一维度为"缺口"且是岗位核心职责 → 总评不得判为高匹配。
- 判"缺口"的维度必须输出到待考察点（走 question-design 的缺口题通道，见第四节），不得只标注不跟进。

## 三、核心优势（3-5 条）

与岗位强相关的差异化优势，每条格式：**优势点 + 简历证据（具体项目/数据） + 与岗位的关联**。
只写与岗位要求相关的优势，不写泛泛的优点。每条证据必须来自简历原文。
**核心优势条目同时是业务面问题设计的首选素材源（高光钩子）**——问题从"他最强的地方"展开，不从"他可疑的地方"展开。

## 四、待考察点（按考察维度归类）

从简历与画像的差异、风险信号中提炼"面试要验证什么"，每条格式：

**待考察点**（一句话）→ 所属维度（数据真实性/能力边界/动机稳定性/行业认知/岗位理解/自我认知等）→ 简历中的触发信号（为什么存疑）→ 验证方式（面试中怎么问、看什么）。

常见风险信号清单（提取简历时主动排查，含跨职能变体）：
- 经历空档：时间线断层 → 验证去向与动机；空档缘由涉及家庭/婚育时**只标注不追问**，验证方式一律转化为工作安排可问项（合规）
- 频繁跳槽：平均在职 <1.5 年 → 验证稳定性与离职归因
- 节点型离职（复合判断，即使平均在职 ≥1.5 年也命中）：≥3 段经历的离职时点集中在同一在职区间（如都卡在第 24-30 个月离开）→ 典型"晋升/涨薪无望即走"，验证成长诉求与对平台的耐心
- **晋升停滞（判据明确化）**：同一职级停留 >3 年且职责范围无扩大 → 停滞信号，考察成长性而非稳定性；>5 年或同岗多段平移无职责跃迁 → 强信号，验证自我驱动与平台选择
- 数据注水（含变体）：成果数字与职责规模不匹配 → 验证口径与个人贡献；**指标无基线/无测量口径**（"满意度+30%""效率显著提升"）→ 验证测量方法与数据来源；**比例类成果缺定义**（"核心人才流失率 18%→9%"）→ 先问"核心人才"怎么界定再谈效果
- **外包/驻场经历**：乙方项目制经历与甲方岗位职级口径不同 → 验证项目归属与个人贡献边界（"参与"还是"负责"、交付物是什么），不按甲方职级直接折算含金量
- 技能声明超经验：简历写了岗位未要求或年限不支撑的能力 → 验证真实水平；**"精通/专家"档自评必须配完整案例验证**（细节追问让候选人描述具体做法与决策），"了解/熟悉"档按实际使用场景问边界，不因自评高档直接采信或一票否决
- 晋升/职责与年限不符：过快或过慢 → 验证真实职级含金量
- 行业跨度大：无相关行业经历但岗位要求行业经验 → 验证迁移能力
- **人群/场景迁移**：同为 HRBP 但研发团队转销售团队、同为运营但 C 端转 B 端等 → 不是行业跨度但同样高危，验证对目标人群特点的预判与打法转换（情境题素材）
- 自我评价与经历张力：自评高但成果支撑弱 → 验证自我认知

**市场校准（英文/海外简历必读）**：上述判据的市场默认值不同，直接套用会误伤。US/EU 场景下：平均在职 2-3 年属正常，连续多段 <12 个月才升为红线；职业空档（裁员、caregiving、sabbatical）常见，不默认视为风险，只作叙事完整性核验；「全日制/统招」无对应概念，删除该判据；IC 在同一层级长期深耕是正常路径，晋升停滞判据须结合 IC / manager track 判断；加州等地竞业限制基本不可执行，不作为风险信号。详见 `en-localization.md` 第七节——**判据降级不等于放弃核验**，仍是圈疑点、中性进入、深挖验证。

**排序规则**：硬性红线相关 → 岗位核心职责相关 → 其余。风险信号的作用是**圈出疑点**，供 question-design 在第三段（验证风险）以 1-2 题集中处理或并入高光深挖的追问——**不是业务面问题的主要来源**（问题主体来自岗位成功要素与高光素材，见 question-design 题源三源制）。

**缺口同样入题**：匹配度判"缺口"的维度（简历完全没提、非"有矛盾"而是"没有"）不再止步于标注——必须作为待考察点输出一条，并交给 question-design 走**缺口题通道**（只问边界迁移，不问"你做过吗"）。

## 输出格式约定

四部分全部为结构化数据（列表/表格），供 question-design 与 html-output 直接引用；不要在分析阶段写冗长散文。
