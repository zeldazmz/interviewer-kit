# 宿主能力映射（host-adapters.md）

本 Skill 只描述**需要什么能力**，不硬编码宿主工具名。下表记录本 Skill 在常见宿主中的实际调用方式；换宿主时，先在本表确认或补充对应映射，再执行。

| 本 Skill 需要的能力 | WorkBuddy（当前主要宿主） | 豆包工作 / 本仓库环境 | 其他宿主（未列出的请补充） |
|---|---|---|---|
| 点选式提问（≤3 次弹窗、每题 2-4 选项、可多选、带题干） | `AskUserQuestion`（参数：`questions[].{header, question, options[{label, description}], multiSelect}`，无 display_option；题干写在 `question`，分组标题写 `header`，选项的「选择影响」写进 `options[].description`） | `interaction_ask`（参数：`questions[].display_option[].{option_id,label,description}`、`multi_select`、`display_message`） | 如宿主无同名工具，找等效点选提问能力，按该宿主参数构造 |
| 简历文件解析（PDF/DOCX/图片） | 宿主相应解析能力 | pdf skill / word skill / 读图能力 | 宿主相应解析能力 |
| HTML 渲染自检（桌面+移动截图） | 无 shot.py 时：浏览器打开目视核对（桌面+手机宽度各看一遍）；也可用无头浏览器截图 | html skill 的 `scripts/shot.py <html路径>` | 宿主相应截图能力 |
| 交付文件/链接 | 宿主文件交付能力 | `present_files` | 宿主文件交付能力 |
| 无语义点选的纯对话宿主 | — | — | 降级为编号选项文字（「回复 1/2/3」），仍保持 ≤3 轮；不影响产物质量 |
| 无截图能力的宿主 | 浏览器目视核对 | `scripts/shot.py` | 本地浏览器打开 HTML，桌面与 375px 各看一遍 |

**最小可用条件**：能读文件 + 能写文件。满足即可运行，点选与截图能力缺失只影响交互顺畅度与自检强度，不影响产物生成。若宿主连文件读写都没有，只能输出纯文本清单，无法交付 HTML。

## 原则

1. **能力优先**：SKILL.md 正文写「用点选式追问收集画像（≤3 次，每次 ≤4 题）」这类能力描述；具体工具名只出现在本文件。
2. **按宿主校准**：上表参数以实际宿主最新 schema 为准——接入新宿主或宿主升级后，先核对一次真实工具定义再调用，不要照抄旧表。
3. **失败回退**：自检工具不可用时，不阻塞交付——改为浏览器目视核对（至少看桌面与手机宽度两态），并在交付说明中注明自检方式。
4. **新宿主接入**：在新环境首次使用本 Skill 时，先跑通 Step 5 的自检，把实际工具名补进上表。
