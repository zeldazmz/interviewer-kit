# Interviewer Kit · v1.1 产品需求文档（PRD）

> 面试官侧人岗匹配问题清单生成器
> *Interviewer-side interview kit* · GitHub: zeldazmz/interviewer-kit · Release: v1.1.0 · 2025-11

---

## 1. 产品定位与目标用户

Interviewer Kit 是一个 Agent Skill（技能包）——在一次对话内，接收简历文件与 JD 文本，自动产出一份**结构化、可编辑、可导出**的面试问题清单 HTML。它的核心目标是让没有经过结构化面试训练的业务面试官，也能拿着一份设计有据、锚定候选人真实经历的问题卡进考场，把"凭感觉"变成"凭证据"。

**目标用户：**

| 角色 | 使用场景 |
|---|---|
| HRBP / 招聘经理 | 作为工具自己用，也作为标准化产出分发给业务面试官 |
| 业务面试官（用人经理） | 不需要自己设计问题，打开 HTML 就能照着问 |
| 猎头 / 外部面评 | 候选人面评结构化，沉淀为岗位资产 |

**不是什么：**

- 不是 AI 面试机器人（不自动语音 / 视频 / 评分）
- 不是题库产品（不提供"50 道通用面试题"）
- 不是 ATS / HRIS 的替代品

## 2. 问题空间：为什么面试官需要"别人帮他设计问题"

业务面试官最常见的面试准备行为：

> 扫一眼简历 → 在脑子里想两个问题（比如"讲讲你最大的挑战""为什么离职"）→ 进考场

这种行为有三个系统性缺陷：

1. **问题不锚定简历**：通用题和候选人的具体经历不产生交叉——候选人随便套一个 STAR 故事就能过关，面试官测不到真实能力
2. **能力判断跳步**：面试官跳过"先摸清候选人的真实事实"这一步，直接做能力推断——结果就是"他说自己带过 20 人团队"和"他真的有 20 人的管理跨度"被混为一谈
3. **节奏失控**：30 分钟下来只聊了两个项目，剩下 25 分钟在水；或者 30 分钟聊了 10 个话题，每个话题都没挖透

HRBP 作为中间方的问题是：每一场面试都要从零写一份提纲，业务面试官还不一定照着问。成本重复，质量不可控。

## 3. 方法论设计

### 3.1 核心主张：面试是预测，不是审计

真做过的人讲经历时自然会冒出颗粒度；审计姿态换不到新事实，只会让候选人进入防御模式。

这套方法论不追求"抓到候选人说谎"，而是追求"让面试官把候选人的真实经历翻出来，并在此基础上判断：这个人在这个岗位上能交付什么、能稳定多久"。

### 3.2 人选画像导读（先于匹配度，中立铺开）

**这是本次 v1.1 新增的分析入口**——在做任何匹配度判断之前，先把候选人"铺"出来。画像导读包含：

| 部分 | 规则 | 作用 |
|---|---|---|
| 一句话定位 | 基于简历事实的客观描述 | 快速识别 |
| 职业路径 | 当简历满足以下任一条件时展开时间线表格（空档行标红）：① 经历 ≥3 段 ② 有 ≥3 个月空档 ③ 有跃迁回退 ④ 同岗平移；否则只用一句话 | 让面试官一眼看到路径复杂度 |
| 能力三栏盘点 | 对称呈现：**已验证的能力 / 自述待验证的能力 / 明确缺失的能力** | 避免"只挑亮点"的卖人感，让面试官天然知道哪里要深挖 |
| 关键数字锚点 | 从简历里抽出所有数字，正负并列，不筛选（例：合同 2280 万 / 回款 1460 万 / **回款率约 64%** / **未回 820 万** / **空档约 3 年 4 个月**） | 让面试官一眼看到需要验证的数字 |

### 3.3 匹配度诊断（降级规则强制约束）

总评只有「高 / 中 / 低」三档，**降级规则不可绕过**：

- 核心职责（硬条件之一）判缺口 → 不得评高
- 履历连续性有 ≥1 年断档且简历无合理解释 → 触发红线 → 不得评高
- 优先项（preferred）判缺口 → 不影响高匹配，但必须落一道 R 类题验证

### 3.4 题源五型（按序出，有硬约束）

```
F 事实摸底（2-3 题）  →  S 成功要素（3-4 题）  →  C 情境前瞻 + 缺口（1-2 题）
   先摸清家底               再测上限                 再看未来适配
                                                    ↓
                                            R 风险验证（1-2 题）
                                                排雷
                                                    ↓
                                            M 动机收尾（1 题）
                                                双向选择
```

**题源五型的硬约束：**

| 类型 | 配额 | 必做约束 |
|---|---|---|
| **F 事实摸底** | 2-3 题 | **必须排最前**，把简历的模糊表述抠成可验证的事实 |
| **S 成功要素** | 3-4 题 | 每个 S 题的设计原理里必须写明**锚定了哪条 F 类摸出的事实** |
| **C 情境前瞻** | 1-2 题 | 同上；**情境题必须有 ≥2 个具体参数**（"给你我们的店铺：客单价 300 元、大促预算减半……"） |
| **R 风险验证** | 1-2 题 | 空档 / 短任期 / 核心缺口等必须落 R 类；用**中性框架 + 选项**进入（"这段时间是家庭安排、创业、还是休息充电？"） |
| **M 动机收尾** | 1 题 | 最后一问；双向选择（候选人要什么 / 岗位给什么） |

### 3.5 管理考察的三步法（防止让没带过队的人编答案）

面试官最容易犯的错：让没带过队的候选人答"如果让你带 20 人怎么搭"。没有真实管理经历的人只能编。

v1.1 引入**管理三步法**——当 JD 核心职责含团队建设与管理时，必走以下顺序：

| 步骤 | 做什么 | 作用 |
|---|---|---|
| **① 定真实管理跨度（F 类题）** | 直接下属几人 / 间接几人 / 考核权谁拿着 / 人事权谁拿着 / 预算权谁拿着 | 用**权责边界**判断他真实管到哪。若无人事权 + 直接下属 <5 人 → **硬缺口**，直接判，跳过后两步 |
| **② 用真实经历探管理动作** | 招过最难的一个岗位？带过最吃力的下属？做过的一次组织调整？劝退过谁？ | **选育用留汰**五维，每一问锚定一个真实的人或事 |
| **③ 外推（仅在前两步有证据时）** | 如果从现在 X 人扩到 20 人，您第一步招谁、为什么？ | 真实经验上的外推，不凭空设计 |

**约束：** 第 ①② 步必做；第 ③ 步无证据时直接跳过，不浪费一问。

### 3.6 措辞与姿态硬约束

| 规则 | 说明 |
|---|---|
| 中文全程用「**您**」 | 禁止「你」；英文用标准面试口吻（"tell me about..." "walk me through..."） |
| 禁反诘句 | "到底"、"是不是……"、"你有没有……" → 一律改成好奇式 |
| 禁题库式措辞 | "再挑一个"、"讲三个例子" → 一律改成"能不能请您从……讲起" |
| 敏感话题用中性框架 + 选项 | 空档、短任期：「这段时间是家庭安排、创业尝试、还是休息充电？方便按月回忆一下吗」 |
| 开场姿态 = 信息收集 | 「先花几分钟把您的基本盘对一下，后面好聊具体打法」——不是审问 |

### 3.7 教学卡结构（8 要素）

每张卡是给面试官看的教学单元，不是直接念给候选人的台词：

```
┌─────────────────────────────────────────────────┐
│ [F] 事实摸底    主问题：能不能请您从第一单讲起  │  ← 题源标签 + 主问题
├─────────────────────────────────────────────────┤
│ 考察维度：一主两副                                │  ← 维度
│ 主：新客突破的能力判断标准                        │
│ 副：立项 / 预算 / 审批全流程认知                  │
├─────────────────────────────────────────────────┤
│ 设计原理：                                        │  ← 方法论锚点
│ 锚定简历"首年 2280 万纯软合同"的模糊表述……       │
├──────────────────────┬──────────────────────────┤
│ 高分锚定              │ 红旗信号                  │  ← 并排双栏（无分值）
│ ├─ 能报出预算来源     │ ├─ 只能说"我们走了流程"  │
│ └─ 能说出客户关键决策人│ └─ 说不清谁拍板          │
├──────────────────────┴──────────────────────────┤
│ 追问路径：                                        │  ← 技巧标签 + 触发信号 + 停止条件
│ [亮点深挖] 那这单里您自己做的那块占多大权重？      │
│   触发：候选人说"都是我们部门一起做的"             │
│   停：已锚定后面 S 类题                           │
└─────────────────────────────────────────────────┘
```

### 3.8 生成后自检清单（十项）

每生成一份问题清单，必须跑过以下十项，不达标卡片重做：

| # | 项 | 标准 |
|---|---|---|
| 1 | 题源覆盖 | F/S/C/R/M 全部齐全 |
| 2 | F 类前置 | F 类 ≥2 且排在全部题的最前面 |
| 3 | 事实锚定 | 每个 S/C/R 题的设计原理里写明锚定的 F 类事实 |
| 4 | 管理三步法 | 核心职责含团队建设时，必走三步、第 ① 步必出 |
| 5 | 标签覆盖 | 11 个追问技巧标签 ≥9 覆盖、单标签 ≤25% |
| 6 | 姿态比例 | 打开型 / 前瞻型 ≥60%、纯核验 ≤2 题 |
| 7 | 专业度 | 情境题 ≥2 个具体参数；无哄人腔 / 水词 |
| 8 | 锚定形态 | 双轴齐备（高分锚定 ↔ 红旗信号）、无分值 / 评级 |
| 9 | 措辞硬约束 | 中文全程「您」、无反诘句 / 题库式措辞 |
| 10 | 管理岗外推 | 无人事权 + 直接下属 <5 人时，外推题不出现 |

### 3.9 时间分配（30 分钟五段）

| 段 | 题源 | 时长 | 意图 |
|---|---|---|---|
| 1 | F 事实摸底 | 4-5' | 把模糊表述抠实，建事实账本 |
| 2 | S 成功要素 | 6-7' | 从他最强的经历聊起，看上限 |
| 3 | C 情境前瞻 | 7-8' | 真实场景让他现场处理，测未来适配 |
| 4 | R 风险验证 | 4-5' | 疑点中性框架进入，排雷 |
| 5 | M 动机收尾 | 4-5' | 双向选择——他要什么、岗位给什么 |

## 4. 产出形态

### 4.1 模块化 HTML（7 个 section）

```
hero       → 人选画像导读（职业路径 / 能力三栏 / 数字锚点）
match      → 匹配度诊断（逐维表 + 降级规则说明）
checkpoints → 待考察点（红线 / 核心 / 一般，三色标签）
biz        → 业务面问题卡（9-10 张，题源五型标签）
hr         → HR 面问题清单（8 节，模式 A 四段模板 / 模式 B 自由）
agenda     → 时间分配表（五段节奏）
footer     → 页脚（版本 / 方法论说明）
```

所有 section 用 `data-mod="xxx"` 标记，JS 渲染引擎按此定位填充内容。

### 4.2 编辑能力

点击任意文字块可就地编辑；编辑后保存到 `localStorage`，再次打开保持。

### 4.3 三通道导出

| 通道 | 内容 | 用途 |
|---|---|---|
| 业务面 | hero + match + checkpoints + biz + agenda | 发给业务面试官 |
| HR 面 | hero + match + checkpoints + hr + agenda | 发给 HRBP |
| 全部 | 完整 7 模块 | 存档 / 分享 |

**导出版式：375px 手机优先**

- 克隆体宽度 375px，html2canvas 自然命中 `@media (max-width:600px)` 的竖版规则
- 正文 14px / 主问题 17px / 间距收窄
- scale 自动按 canvas 上限调整（iPhone 3x scale → 1125px 物理分辨率）
- PNG 超过 ~12 MB 自动降级 JPEG
- 分段渲染避免长图白屏
- 导出失败弹 toast，busy-lock 防双击

## 5. 输入协议

### 5.1 三种输入方式

| 方式 | 输入 | 画像采集弹窗次数 | 适用场景 |
|---|---|---|---|
| 默认 | JD + 简历 | ≤3 次（可合并） | 首次招某岗位 |
| 岗位库 | 内置岗位 + 简历 | ≤1 次 | 同类岗位重复招聘 |
| 仅简历 | 简历 | ≤1 次 | 无 JD 时，匹配度标注"缺少岗位锚定" |

### 5.2 画像采集弹窗（硬约束）

- 岗位方向（自由文本）
- 职级与汇报关系（自由文本）
- 公司阶段（选项：早期 / 成长期 / 成熟稳定期）
- HR 面模式（选项：四段模板 / AI 自由发挥）
- **成功要素**（必做，2-3 条，禁止形容词堆砌，必须含可观察的行为 + 可量化的产出）

冲突优先级：用户改选 > profile_notes > JD 抽取 > 默认值

## 6. 合规硬约束

1. **禁婚育问项**：不问婚育 / 家庭情况；稳定性考察一律转为工作安排相关（"您的时间安排能覆盖每月 X 天出差吗"）
2. **海外岗位不套用中文措辞**：英文产物按 `en-localization.md` 重构——Work Authorization / Compensation Expectations / Role Alignment / Motivation & Availability
3. **学历、流水、履历核验**归 HR 面与背调，业务面只保留与能力直接相关的口径问题
4. 候选人隐私数据（姓名、电话、邮箱、身份证）**不得进入仓库样例**；样例使用虚构姓名与虚构公司

## 7. v1.1.0 升级摘要（相对 v1.0.0）

| 维度 | v1.0.0 | v1.1.0 |
|---|---|---|
| 分析入口 | 匹配度 + 核心优势（从结论倒推） | 画像导读（中立铺开） → 匹配度（自然产生） |
| 题源 | 三源制（成功要素 / 情境前瞻 / 风险验证） | 五型（F 事实摸底必排前 / S / C / R / M） |
| 管理考察 | 无专门方法，直接按成功要素出题 | 三步法（权责 → 经历 → 外推，无人事权直接判缺口） |
| 措辞 | 无硬约束 | 中文全程「您」、禁反诘句 / 题库式 / 审判姿态 |
| 事实锚定 | 可选说明 | 硬约束：每个 S/C/R 题必须锚定 F 类事实 |
| 导出 | 750px 桌面版（有意为之） | 375px 手机版（转发友好） |
| 画像条件展开 | 无（一刀切渲染） | 路径复杂 / 有断档才展开时间线 |
