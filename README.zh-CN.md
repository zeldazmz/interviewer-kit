# interviewer-kit · 面试官侧人岗匹配问题清单生成器

[English](README.md) · [中文](README.zh-CN.md)

---

> **面试官侧人岗匹配问题清单生成器 · Interviewer-side interview kit**

## 痛点

业务面试官多数没有接受过结构化面试训练。手里只有一份简历和一段岗位描述，能问出口的往往是"介绍一下你自己""为什么离职""这个项目你做了什么"。三十分钟过去，判断依据主要是表达是否流畅、气场是否合拍，而不是这个人能否在岗位上交付。

同一岗位换两位面试官，结论往往对不上：有人看行业背景，有人看沟通感觉，最终决策退回到"我觉得还行"。成本落在 HRBP 身上——每场面试重新写一份提纲，还不知道业务方会不会照着问。

## 解决方案

两份输入，一份交付物。JD 用来确定岗位真正要求什么——硬条件、优先项、可迁移能力；简历用来定位候选人主动强调的成果。问题从两者的交叉点产生，不从通用题库里挑。

每张卡写明问题本身、设计依据、合格回答应包含什么、红旗信号长什么样、以及如何追问。产物是单文件 HTML：任何一行都能就地修改，导出长图后直接发给面试官。

```
JD 文本 / 简历文件           一次对话
      │                         │
      ▼                         ▼
┌──────────────┐          ┌──────────────┐
│ 核心要求提取   │          │ 标志性成果锚定  │
│ 哪些硬条件     │  ──►    │ 哪几个项目能   │
│ 哪些优先项     │          │ 证明这些条件   │
│ 哪些可迁移     │          │                │
└──────────────┘          └──────────────┘
      │                         │
      └─────────┬───────────────┘
                ▼
          问题卡 + 节奏表
                │
                ▼
         可编辑 HTML
                │
                ▼
         750px 长图导出
          （微信 / Slack / Lark 直接发）
```

三种输入方式：JD 与简历（默认）；常用岗位库中的岗位与简历（跳过 JD 采集，适合同类岗位重复招聘）；仅简历（按通用画像出卡，匹配度明确标注"缺少岗位锚定"）。

## 价值

| 价值 | Value |
|---|---|
| **判断有依据** — 每条结论都能对应到简历或回答中的具体证据，不是印象分 | **Evidence-based** — every judgment traces to a specific line in the resume or a specific answer |
| **标准可对齐** — 同一岗位共用一套评估维度与问题锚点，多位面试官的结论可横向比较 | **Comparable** — one set of dimensions and anchors per role |
| **准备只做一次** — HRBP 输入一次即可分发，不必逐场重写 | **Prepared once** — input once, distribute to all interviewers |
| **可持续复用** — 问题卡沉淀为岗位资产，下次招聘同类岗位直接调用 | **Reusable** — cards accumulate as role assets |

## 两个使用场景

### 面试前准备

HRBP 把岗位描述与简历一起提交，确认一次画像，即得到该岗位的完整清单：匹配度诊断、待考察点、九张问题卡、30 分钟节奏表。审阅一遍，改掉不适用的提问、补上需要的追问，导出长图发到面试官群。面试官在开始前十分钟打开，知道这 30 分钟要问什么、听到什么算过关。

### 面试中提问

面试官按节奏表推进：先用开放问题让候选人讲完，再对照卡上的高分锚定与红旗信号判断回答落在哪一侧。回答含糊时，沿卡上的路径追问——拆开数字构成、要时间线、问失败案例——而不是临场想问题。既不冷场，也不会因为追问过密把候选人逼进应试状态。

### 输入

<details><summary>JD（精简版，Northwind Supply）</summary>

> **高级增长经理** · Northwind Supply · B 轮可持续家居品牌 · 美国远程 · 底薪 $140–170K + 0.15% 股权激励 + 浮动
>
> 端到端负责增长漏斗；带领 5–8 人增长营销团队；管理 $240 万年付预算，维持混合 CAC 约 $38；与产品团队协作优化转化。DTC / 消费类增长经验 7 年以上。数据驱动，熟练使用 SQL。**优先项**：Shopify Plus、SMS 营销（Klaviyo）、创作者合作。

</details>

<details><summary>简历（精简版，Alex Johnson）</summary>

> 7 年消费类电商用户获取与留存经验。曾带领 DTC 宠物品牌（PawPrints）把月营收从 $0 做到 $240 万，CAC 维持在 $41。搭建 Klaviyo 推荐计划，贡献了 18% 的新用户、CAC 仅 $19（比任何付费渠道都低）。上一任：EdTech 创业公司，用户从 0 做到 32 万，CAC $39 → $26。带过 7 人团队（18 个月里 1 人离职）。目前 14 个月咨询空档——三个早期 DTC 项目。SQL、Looker、Shopify Pro、Klaviyo、TikTok Ads。**两段短任期**（PawPrints 18 个月，EdTech 2.5 年）。

</details>

### 技能产出什么

**1. 匹配度诊断**——不是打分表，是诊断。

| 维度 | 判定 | 依据 |
|---|---|---|
| 年限、结果 ownership、CAC 记录 | ✅ 达标 | 7+ 年，DTC 规模化，增长时控住 CAC |
| 数据栈（SQL、Looker）、团队建设 | ✅ 达标 | SQL + Looker，带过 7 人，18 个月 1 人离职 |
| DTC 商业模式 | ✅ 达标 | PawPrints 和 LearnSphere 都是 DTC/消费类 |
| 预算规模匹配 | ⚠️ 部分 | Northwind 是 $240 万年付；他做过的最大是混合口径，需确认顶层漏斗 ownership |
| 可持续家居品类迁移 | ❌ 缺口 | 宠物 vs 家居；购买频次和决策心态不同 |
| Shopify Plus（JD 优先项） | ❌ 缺口 | 用过 Shopify Pro，不是 Plus |
| 综合 | **中** | 成果扎实 + 稳定性风险（两段短任期 + 14 个月空档） |

**2. 六条待考察点**——带**怎么验证**：

| 信号 | 类型 | 追问方向 |
|---|---|---|
| 14 个月咨询空档 | 红线 | 确认项目交付物；只问事实，不问个人隐私 |
| 两段短任期（18 个月 + 2.5 年） | 核心 | 离职逻辑；决策模式是否重复？ |
| "$41 混合 CAC" 归因 | 核心 | 包含了哪些？哪个具体渠道/动作把它从 $45 的目标拉下来的？ |
| 7 人团队 — 1 人离职 | 核心 | 离职时间是否与创始人策略调整重合？有没有主动淘汰过？ |
| 预算规模匹配 | 一般 | 他做过的最大混合 vs Northwind 的 $240 万年付——会怎么调整分配？ |
| 可持续家居品类迁移 | 一般 | 60 天内怎么快速学习这个品类——永远不问"你卖过家居吗？" |

**3. 九张问题卡**——下面是其中一张的原文：

```
Q1 · 主维度：规模化 CAC 控制 · 副维度：口径真实性、预算 ownership

问题
你在 PawPrints 把混合 CAC 维持在 $41——低于初始 $45 目标——
同时把月营收从 $0 做到了 $240 万。拆解一下这个 $41：
包含哪些成本？哪个具体渠道或动作把它从 $45 拉下来的？
规模化阶段（第 10–18 个月）CAC 的走势怎么样？

为什么这样问
直接锚定 JD 的核心要求："增长的同时维持 CAC 稳定"。
要求拆解构成 + 时间序列趋势，是区分"一个月异常值"和"真正的趋势"最快的方式——
真操盘的人知道季度走势，不会只说一个 headline 数字。

高分锚定
· 能报出三个渠道各自的 CAC vs 混合口径
· 能说出一个具体动作（TikTok 素材刷新、推荐计划 K 值调优）
· 诚实描述第 10–18 个月的走势——不是一条平坦直线，有上下文
· 提到成本反弹或饱和度，哪怕 CAC 最终维持住了

红旗信号
· 只有总数，没有渠道构成
· 归因为"投放效率更高了"——没有具体抓手
· 声称规模化阶段每个月 CAC 都一样（不现实）
· 说不清数字里包含了什么

追问
[对口径]          这个 $41 包含推荐成本吗？还是只算媒体投放？
[时间线验证]      第 18 个月之前，每个月 CAC 都低于 $41 吗？
[压力测试]        预算砍 20%——保哪个渠道、砍哪个、怎么重新分配？
[反例法]          有没有哪个渠道没撑过 90 天？什么原因关掉的？
```

每张卡都写明：问什么、为什么这样问、合格回答应包含什么、红旗信号是什么、以及如何追问。

**4. 节奏表**——30 分钟业务面、30 分钟 HR 面，带节奏要点。

**5. 可编辑 HTML 导出**——点击任意位置可编辑，导出成长图 PNG 或 JPEG。中文产物 750px 版式（1.75x scale 清晰）+ 移动端单列阅读视图；英文产物同版式，`lang="en"` 时界面字符串自动切换。

## 工作流

技能在一次对话中完成（Agent 触发一次）。五步，每步都有明确的停止条件——上一步的输出不符合规范，Agent 不能进入下一步。

| 步骤 | 输入 | 输出 |
|---|---|---|
| 1. 画像采集 | 简历文件 + JD 文本 | 结构化画像 + 3 条成功要素 |
| 2. 分析 | 结构化画像 | 匹配度诊断 + 逐维判定 + 待考察点 |
| 3. 问题设计 | 分析 + 成功要素 | 问题卡（业务面 + HR 面） + 节奏表 |
| 4. 自检 | 完整问题清单 | 十项检查清单；不达标卡片必须重做 |
| 5. HTML 打包 | 所有前置输出 | 可编辑 HTML 文件，导出即用 |

自检不是装饰性的。实测中它抓到了真实失败——比如"跨部门影响力只出现在副维度，主维度里完全缺失"——并强制重新设计。

## 功能清单

### 方法论层

- **三源制题源**：成功要素卡（4–5 张，测上限）· 情境前瞻卡（1–2 张，测未来适配）· 风险验证卡（1–2 张）。配额存在，但"为凑配额出题"被明确禁止
- **缺口题通道**：如果 JD 列了一个"优先项"而简历没有，问题永远是"你怎么补上这个缺口"——永远不问"你做过吗"
- **问题卡结构**：主问题 → 主/副维度 → 设计原理 → 高分锚定 ↔ 红旗信号 → 追问路径（带 *标签 + 触发信号 + 停止条件*）
- **中性风险框架**：空档、短任期等风险先用中性框架验证（"我想先确认一下时间线再往下聊"），不是审判式追问

### 工程层

- 单文件 HTML，内联渲染引擎（html2canvas），无 CDN，断网可用
- 手机端 = 375px 单列阅读视图；导出 = 750px 桌面版式（有意为之，非 bug——1.75x scale 保证清晰度）
- 自适应 canvas scale（上限 16Kpx），长图分段渲染，PNG 超过 ~12 MB 自动降级 JPEG
- 导出失败弹 toast；不会悄悄生成白图然后"成功"
- 导出按钮 busy-lock，防止双击崩溃
- 宿主适配器设计（见 [`references/host-adapters.md`](references/host-adapters.md)）：只写能力层描述，不硬编码工具名

### 国际化

- 产物语言跟随**面试语言**，不跟随操作者语言
- 英文本地化（`references/en-localization.md`）：术语、句式、11 个追问标签变体
- US / EU / UK 合规红线：年龄、婚育、国籍、残疾、薪资历史——每项标注"可问 / 不可问"并附区域说明
- HR 面试四段**为英文路径重构**，不是翻译（四段模板替换了中文版）
- UI 字符串集中在 `I18N` 对象；按钮、toast、确认框、导出文件名全部自动切换

## 快速上手

### 方式 A —— 你的 agent 支持 skills

1. Clone 或下载本仓库
2. 把 `interviewer-kit/` 文件夹放进 agent 的 skills 目录
3. 重启 agent，然后说：
   > "帮我用 interviewer-kit 生成面试清单，附件是候选人简历"

### 方式 B —— 你的 agent 不支持 skills

把 `SKILL.md` + `references/` 下 6 个文件的内容一次性粘贴进会话作为上下文，然后用同样的方式提问。技能完全靠 markdown 指令驱动——零代码执行。

### 宿主适配器说明

技能用**能力描述**写的（"向用户提一个结构化问题"、"写出 HTML 文件"），不是工具名。如果你的 agent 用不同的工具标识符，在 [`references/host-adapters.md`](references/host-adapters.md) 里加一行映射就行。

## 适用范围与边界

**为以下场景设计**：B2B、SaaS、增长、运营、财务、职能支持等知识工作面试——任何"过往成果能预测未来表现"、"JD 技能能映射到简历行为"的岗位。

**以下场景效果较弱**：预测力弱的岗位（比如早期"潜力型"校招、高度创意型岗位的作品集）、或有强制面试格式的强监管行业（临床、制造质量等）。技能仍然会产出东西，但应该视为**草稿**，需要你再加工。

**不用于**：替代法律或合规审查。合规说明仅供参考——正式使用前请与你所在区域的法务或合规负责人确认。

## 合规与数据处理

- 无遥测，无分析。技能运行时不向外发起网络请求。
- 产物是单个 HTML 文件。生成后不收集、不存储、不传输 PII。
- 技能内置了禁止问题的护栏（婚育、年龄、薪资历史、残疾等）。但这不是穷举。
- 分享产物给他人时，如果你的组织把面试材料视为敏感信息，考虑把候选人全名替换成角色标识（比如"Cand-A · 增长经理"）。
